# HAM10000: VAE-Based Synthetic Minority-Class Augmentation

Does balancing a naturally imbalanced skin-lesion dataset with class-specific
VAE-generated synthetic images improve a DenseNet-121 classifier's
minority-class recognition — compared to the original imbalanced data and a
classical oversampling control?

**Full write-up with methodology, results tables, and discussion:**
[`reports/FINAL_REPORT.md`](reports/FINAL_REPORT.md) (also available as
[`.docx`](reports/HAM10000_VAE_Project_Final_Report.docx)).

## TL;DR result (single seed, see report for full discussion)

| Condition | Macro-F1 | Balanced Acc. | vs. baseline (95% CI) |
|---|---|---|---|
| C0 — original imbalanced data | 0.6165 | 0.5953 | — |
| C1 — classical oversampling | 0.5831 | 0.6054 | not significant |
| **C2 — VAE, 50% balancing cap** | **0.6497** | **0.6393** | not significant |
| C3 — VAE, fully equalized | 0.6489 | 0.6320 | not significant |

VAE-based balancing (C2, C3) beat both the imbalanced baseline and classical
oversampling on every summary metric, with a clean monotonic improvement in
recall for the rarest class (`df`: 0.167 → 0.333) and a recovery in melanoma
(`mel`) recall. None of the differences reached statistical significance at
this single seed — the honest conclusion is a **promising, unconfirmed
positive trend**, not a proven result. See the report for the full
per-class breakdown and discussion of why C1 underperformed while C2/C3 did
not.

## Method summary

- **Dataset:** [HAM10000](https://www.kaggle.com/datasets/kmader/skin-cancer-mnist-ham10000),
  7 diagnostic classes, naturally imbalanced (majority `nv`: 6,705 images;
  minority `df`: 115 images, ~58:1 ratio at the full-dataset level).
- **Split:** grouped by `lesion_id` (not by image) to prevent leakage from
  near-duplicate images of the same lesion; stratified per class so every
  class appears in train/val/test.
- **Classifier:** DenseNet-121 (ImageNet-pretrained), identical architecture
  and training schedule across all conditions — a two-stage fine-tune
  (frozen backbone → unfrozen final block), plus an optional short
  real-images-only polish phase for conditions using synthetic data.
- **VAE:** one convolutional VAE per minority class, trained only on that
  class's real training images, with flip/rotation augmentation. Synthetic
  images are generated by interpolating between two real images' latent
  codes ("manifold" sampling) rather than sampling the prior directly —
  this was found during development to noticeably outperform naive prior
  sampling.
- **Conditions compared:** C0 (imbalanced baseline), C1 (classical
  inverse-frequency oversampling), C2 (VAE-balanced to 50% of majority), C3
  (VAE-balanced to full equality).

## Running it yourself

The easiest path is the self-contained Kaggle notebook:

1. Upload `notebooks/HAM10000_Kaggle_Notebook.ipynb` to a new Kaggle Notebook.
2. Add Input → attach `kmader/skin-cancer-mnist-ham10000`.
3. Turn on GPU, run cells top to bottom, saving a version at each session
   checkpoint (see the notebook's own markdown notes — a full run doesn't
   fit in one Kaggle session on the free tier).

Or, on your own GPU machine:

```bash
pip install -r requirements.txt
bash run_pipeline.sh audit
bash run_pipeline.sh split
bash run_pipeline.sh baseline 17
bash run_pipeline.sh train_vaes 17
bash run_pipeline.sh generate 17 C3
bash run_pipeline.sh retrain 17 C3
bash run_pipeline.sh evaluate 17 C3
```

See `run_pipeline.sh` for all phases (`audit`, `split`, `baseline`,
`train_vaes`, `generate`, `retrain`, `evaluate`).

## Known limitations

- **Single seed.** The design calls for 3 seeds (17, 29, 41) with aggregated
  confidence intervals; only seed 17 was fully run. The reported "not
  significant" result should be read as suggestive, not confirmatory —
  re-running the remaining seeds is the natural next step for anyone
  continuing this work.
- No reliable patient-ID metadata in the original HAM10000 release, so
  splitting is done at the lesion level, not patient level.
- Academic benchmark exercise, not a validated clinical tool.
